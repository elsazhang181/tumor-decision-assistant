## 一、项目概述

### 1.1 项目定位

「健康就医决策助手」是一个面向患者及家属的 AI 就医辅助平台，核心价值是：

- **把复杂的医学信息翻译成患者能听懂的语言**
- **帮助患者在关键时刻做出"见到医生该问什么"的辅助参考**
- **陪伴患者走完从症状出现到复查随访的就医全程**

### 1.2 核心定位原则

- **不诊断、不开药、不替代临床诊疗**
- **安全第一**：每次回复先做紧急程度判断，急症情况永远置顶
- **赋能患者**：不做决策，但帮患者把"该问的问题"问出口
- **措施具体**：给出方向性建议，而非模糊表述

### 1.3 线上地址

- **前端网站**：https://web-production-200f3.up.railway.app （全域公开、24小时可用）
- **AI 智能体**：Coze 平台 Bot（后端 AI 服务）
- **代码仓库**：Coze Sandbox 开发环境

| 组件 | 平台 | 职责 |
|------|------|------|
| **健康就医网站** | Railway | 前端界面，用户交互，UI 渲染 |
| **健康就医决策助手** | Coze | AI 智能体，问题处理，回复生成 |

前端网站通过 Coze Bot API 调用智能体获取 AI 回复，两者通过 HTTPS + SSE 协议通信。

## 三、功能模块设计

### 3.1 五大核心模块

| 模块 | ID | 色系 | 功能描述 |
|------|-----|------|---------|
| 健康自查 | symptom-check | 橙色 | 症状评估，信号识别，紧急程度判断 |
| 检查治疗 | treatment-plan | 蓝色 | 检查报告解读，治疗方案参考 |
| 用药咨询 | medication | 绿色 | 药物信息，医保甲类乙类查询 |
| 慢病管理 | chronic-disease | 青色 | 长期管理，日常监测，复查节奏 |
| 就医指导 | medical-guidance | 紫色 | 异地医保，转诊保险，报销政策 |

### 3.2 模块自动匹配机制

系统实现了基于关键词评分的意图识别机制：

- **核心关键词**（2分）：直接匹配模块主题的词
- **相关关键词**（1分）：间接关联的词
- 当用户输入问题时，系统自动计算各模块得分，选择最高分模块
- 得分相同时保持当前模块不变

### 3.3 三种对话模式

| 模式 | 标识 | 说明 |
|------|------|------|
| 即时问答 | instant | 无上下文，每次独立对话，适合快速查询 |
| 患者随访 | patient | 有上下文，保持对话连续性，适合长期跟踪 |
| 多患者管理 | multi-patient | 并行管理多个患者会话，适合医生/家属 |

## 四、Bot 提示词设计（核心）

### 4.1 角色定位

Bot 被设定为「就医决策陪伴助手」，遵循以下核心原则：

1. **安全第一**：急症关键词命中时，立即中断常规流程，优先输出急救指引
2. **结构适配内容**：根据问题类型自动匹配最合适的回复模板
3. **时间轴锚定**：三段行动指引按"此刻→诊中→归家"时间线区分
4. **简化优先**：用生活比喻替代医学术语，每段不超过3个核心要点
5. **赋能患者**：帮患者把"该问的问题"问出口
6. **措施具体**：给出明确的缓解方案或处理方向

### 4.2 回复流程

```
用户输入
  │
  ▼
步骤一：安全闸门（必做）
  │ 扫描急症关键词
  │ 命中 → 🔴立即就医标签 + 急救指引
  │
  ▼
步骤二：问题类型识别
  │ 关键词匹配 → 5种场景模板之一
  │
  ▼
步骤三：按匹配模板输出回复
  │ 结构化回复（结论→解释→行动→清单→管理）
  │
  ▼
步骤四：来源依据
  │ 列出 2-4 条信息来源
  │ 标注类型和时效性
  │
  ▼
步骤五：兜底声明
  │ "以上信息仅供参考，不能替代专业医生诊断"
```

### 4.3 五大场景模板

#### 模板一：症状评估
```
【紧急程度】🔴立即就医 / 🟡24h内就医 / 🟢预约就诊 / ⚪居家观察
【核心结论】一句话核心回答 + 一句话行动建议 + 具体措施
【通俗解释】生活化比喻解释医学概念
【📍 此刻行动】就医前马上做的准备
【💬 问诊清单】3-5个替患者拟好的问句
【🏠 居家管理】预警信号 + 日常监测 + 生活注意
```

#### 模板二：治疗方案
```
【核心方向】基于 CSCO 指南的治疗方向
【方案解读】生活化比喻 + 选项对比
【🔀 决策框架】"如果…就…"结构
【💬 问诊清单】向主治医生确认的问题
【🏠 治疗注意】治疗前/中/后的注意事项
```

#### 模板三：用药咨询
```
【核心信息】药物作用 + 医保状态（甲类/乙类）
【通俗解释】生活化比喻解释药物机制
【用药须知】服用方法 + 饮食禁忌 + 副作用
【医保参考】报销方向 + 集采信息
【💬 问诊清单】用药相关确认问题
【🏠 用药注意】严重副作用信号 + 日常监测
```

#### 模板四：慢病管理
```
【管理重点】核心管理要点一句话概括
【日常监测】监测项目 + 频率 + 方法
【🚨 预警信号】分级别（立即急诊/24h内/下次复诊）
【复查节奏】复查频率 + 检查项目
【💬 下次问诊清单】复查时确认的问题
【🏠 日常管理】饮食 + 运动 + 生活调整
```

#### 模板五：就医流程
```
【核心指引】一句话回答（以官网信息为依据）
【分步流程】编号步骤说明操作流程
【📍 此刻准备】出发前确认清单
【🏠 注意事项】全程注意事项 + 常见坑
```

### 4.4 来源引用规范

- 列出 2-4 条信息来源
- 标注类型：🏥 医院指南 / 📋 政府官网 / 📰 行业媒体 / 📚 专家共识 / 📖 知识库资料
- 标注时效性：高（2025-2026）/ 中（2023-2024）/ 低（2022前）
- 禁止虚构来源，无明确来源时不写此段

### 4.5 回答一致性保障

- API 调用时设置 `temperature: 0`，减少随机性
- 即时问答模式附加"严格回答要求"提示词，要求引用具体权威来源
- 要求给出明确的具体数字、比例、时间等关键信息

### 5.2 设计要点

- **模块栏**：横向单行紧凑布局，点击切换模块，下方展开说明面板
- **流式输出**：通过 SSE + ReadableStream 实现打字机效果
- **Markdown 渲染**：使用 marked 库渲染 AI 回复
- **响应式设计**：适配手机/平板/桌面端
- **移动端优化**：
  - 标题层级压缩（h1: 1.1em, h2: 1.05em, h3: 0.95em）
  - 正文 13px（移动）/ 14-15px（桌面）
  - 键盘弹出时自动调整布局
- **超时处理**：55秒超时检测 + "重新生成"按钮
- **历史记录**：localStorage 存储，支持搜索/删除/清空

### 5.3 患者管理功能

- **患者会话**：每个患者独立会话，包含姓名、疾病阶段、Coze 会话ID
- **多患者并行**：支持同时管理多个患者的对话
- **数据持久化**：localStorage 存储患者列表和对话历史
- **会话连续性**：通过 Coze conversation_id 保持上下文

## 六、部署架构

### 6.1 Railway 部署

#### Dockerfile
```dockerfile
FROM node:20-alpine
RUN corepack enable && corepack prepare pnpm@9.0.0 --activate
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile
COPY . .
RUN pnpm build
EXPOSE 3000
ENV PORT=3000
CMD ["pnpm", "start"]
```

#### 关键配置
- **端口**：3000（Railway 自动映射到公网）
- **构建**：pnpm build（Next.js 生产构建）
- **运行**：pnpm start（Next.js 生产服务）
- **域名**：web-production-200f3.up.railway.app

#### 环境变量
| 变量名 | 说明 | 示例值 |
|--------|------|--------|
| COZE_API_TOKEN | Coze 平台 Personal Access Token | pat_xxxxx |
| COZE_BOT_ID | Bot ID | 7633265670037323818 |
| COZE_API_BASE_URL | Coze API 基础地址 | https://api.coze.cn |

### 6.2 Coze 平台配置

#### Bot 设置
- **平台**：Coze 中国版（coze.cn）
- **API 版本**：v3/chat（流式输出）
- **认证方式**：Personal Access Token (PAT)
- **Bot 提示词**：配置在「人设与回复逻辑」中

#### 提示词配置步骤
1. 登录 Coze 平台（coze.cn）
2. 进入「健康就医决策助手」Bot
3. 点击左侧「人设与回复逻辑」
4. 将完整提示词（见 assets/coze-bot-prompt.md）粘贴进去
5. 发布 Bot

## 七、API 通信协议

### 7.1 请求流程

```
前端 page.tsx
  │ fetch POST /api/chat
  │ body: { message, mode, conversationId, ... }
  │
  ▼
后端 route.ts
  │ 构建 Coze API 请求
  │ POST https://api.coze.cn/v3/chat
  │ headers: Authorization: Bearer <token>
  │ body: { bot_id, user_id, stream: true, additional_messages }
  │
  ▼
Coze API
  │ SSE 流式返回
  │ event: conversation.chat.created
  │ event: conversation.message.delta（文本块）
  │ event: conversation.message.completed
  │ event: conversation.chat.completed
  │
  ▼
后端 route.ts
  │ TransformStream 转发
  │ 提取 conversation_id
  │
  ▼
前端 page.tsx
  │ Reader 逐块读取
  │ 打字机渲染
```

### 7.2 关键参数

| 参数 | 说明 |
|------|------|
| bot_id | Bot 唯一标识 |
| user_id | 用户标识（即时模式为 anonymous） |
| stream | 是否流式输出（true） |
| auto_save_history | 是否自动保存历史 |
| conversation_id | 会话ID（患者模式需要） |
| additional_messages | 用户消息内容 |
| temperature | 随机性控制（即时模式设为 0） |

### Railway 环境变量

| 变量名 | 必填 | 说明 |
|--------|------|------|
| COZE_API_TOKEN | 是 | Coze PAT，用于 API 认证 |
| COZE_BOT_ID | 是 | Bot ID，标识目标智能体 |
| COZE_API_BASE_URL | 否 | 默认 https://api.coze.cn |

### Coze 平台配置

| 配置项 | 说明 |
|--------|------|
| Bot 名称 | 健康就医决策助手 |
| 人设与回复逻辑 | 完整提示词（见 coze-bot-prompt.md） |
| Temperature | 0（确保回答一致性） |
| 联网搜索 | 开启（获取最新政策信息） |
